# openvoice_setup

Everything customised on the home OpenVoiceOS Raspberry Pi (Debian 13 trixie, aarch64) on top of a
stock [ovos-installer](https://github.com/OpenVoiceOS/ovos-installer) run, so the box can be rebuilt from scratch.

No secrets or host-specific identifiers are stored here. Tokens and keys are `${PLACEHOLDERS}` filled from a git-ignored `setup.env` at
install time, and the login user, LAN IP and UID/GID are `__TOKENS__` replaced by `install/apply.sh`; the familIA proxy's AWS credentials live only in `/etc/familIA/proxy.env` on the Pi.

Related repositories:

| Repo | What |
|---|---|
| [familIA](https://github.com/mahdsip/familIA) | Lambda + API Gateway `/ask` (the LLM brain), Terraform, original proxy script |
| [home-mcp](https://github.com/mahdsip/home-mcp) | MCP server (Home Assistant, Plex, Nextcloud, PhotoPrism, Prometheus) the proxy calls over SSH. Installed on its own host; not duplicated here |

## Architecture

```
mic -> OVOS (wake word, STT, intents) --skills--> Home Assistant, Plex, OCP ...
                     |
                     +-- no intent matched -> persona "familIA" -> familIA proxy (127.0.0.1:8080)
                                                                    |-- SigV4 --> API Gateway /ask (familIA Lambda)
                                                                    '-- ssh, forced command --> home-mcp tools
browser -> HiveMind webchat (:9090) -> HiveMind core (:5678) -> OVOS messagebus (127.0.0.1:8181)
browser -> Open WebUI (:3000) -> familIA proxy (no OVOS: no skills, no Home Assistant control)
```

## What is customised

| Area | Files | Why |
|---|---|---|
| OVOS config | `ovos/config/mycroft.conf` | es-ES, Vosk STT (`vosk-model-small-es-0.3`), Piper TTS `es_ES-sharvard-medium`, wake word "hey tiki" (Vosk, `contains` rule; "hey mycroft" disabled), Silero VAD, intent pipeline with the familIA persona last |
| familIA persona | `ovos/config/ovos_persona/familIA.json` | OpenAI solver pointed at the local proxy |
| Skill settings | `ovos/config/skills/*/settings.json`, `ovos/config/apps/*` | Home Assistant URL/token, Plex URL/token, alerts, disabled Wolfram |
| Plex skill | `skills/ovos-skill-plex/` | own skill (`ovos-skill-plex.mahdsip`), Spanish locale |
| OCP Spanish intents | `patches/ovos-ocp-pipeline-plugin-1.1.18-es-play-intent.diff` | adds "pon/ponme música de ...", "quiero escuchar ...", playlists |
| HiveMind core | `hivemind/config/server.json`, `systemd/system/hivemind-core.service` | websocket on the LAN IP, agent on the local messagebus |
| HiveMind webchat | `hivemind/webchat/` + `patches/hivemind-*.diff` | see below |
| familIA proxy | `familia-proxy/` | deployed version (newer than `familIA/scripts`), incl. the MCP bridge |
| Open WebUI | `open-webui/env.example`, `systemd/system/open-webui.service` | chat UI on the proxy, 1.6 GB memory cap, sign-ups pending approval |
| systemd | `systemd/` | all OVOS/HiveMind/proxy/Open WebUI units and drop-ins (mimalloc, RT priority, no swap), tmpfs state sync, apt upgrades at 03:00, tty1 autologin |
| System tuning | `system/etc/` | sysctl, zram/swap, BFQ scheduler, USB audio, tmpfs for `/tmp` and OVOS state |
| Audio / desktop | `user-config/` | PipeWire low latency + noise suppression, WirePlumber capture volume/no idle, labwc/kanshi |
| Python envs | `requirements/` | exact `pip freeze` + Python version of each venv |

Most of `systemd/`, `system/` and `user-config/` is generated by ovos-installer's tuning step; it is kept so a
rebuild ends up identical even if the installer changes.

### HiveMind webchat fixes

Upstream `hivemind-webchat` 0.2.2 loads its JS from `jarbashivemind.github.io` and binds to all interfaces. Here:

- `static/js/vendor/` vendors `asmcrypto.js`, `webcrypto-shim.js` (identical to upstream) and a patched
  `hivemind.js` (`patches/hivemind-js-vs-upstream.diff`):
  - per-browser session id (HiveMind 4 rejects non-admin clients on the shared `default` session);
  - replies to the server `HELLO` with that session. Without it HiveMind never registers the client: answers were
    spoken on the Pi's speaker instead of shown in the chat;
  - decrypts replies as UTF-8 (accents were garbled);
  - sends `lang: es-ES`.
- `templates/index.html` loads the vendored scripts with a `?v=` cache-buster (bump it after changing the JS).
- `hivemind-webchat-local` binds Tornado to `WEBCHAT_BIND` (default loopback) instead of every interface.

## Rebuild

1. Flash Raspberry Pi OS (Debian 13) and run ovos-installer (Spanish, tuning on). Reserve the
   Pi's IP on the router if the services will be exposed on the LAN.
2. On the Pi: `sudo apt install gettext-base patch rsync git unzip curl` and clone this repo.
3. `cp setup.env.example setup.env` and fill it in. `BIND_IP` defaults to `127.0.0.1` (nothing exposed); set the
   Pi's LAN IP to use the webchat, HiveMind and Open WebUI from other devices.
4. `./install/apply.sh` (or individual sections: `system user systemd ovos hivemind proxy openwebui`).
5. Manual steps the script prints:
   - fill `/etc/familIA/proxy.env` (`sudoedit`, template in `familia-proxy/proxy.env.example`);
   - create the webchat client: `~/.venvs/hivemind/bin/hivemind-core add-client --name webchat-casa`, and enter
     its access key and crypto key in the webchat page;
   - optional home-mcp tools: set `MCP_SERVER_COMMAND` and authorise the proxy key on the MCP host
     (home-mcp `deploy/authorize_proxy_key.sh`);
   - Open WebUI: open `http://<BIND_IP>:3000`, create the admin account first, then disable sign-ups.
6. `sudo reboot` (fstab/sysctl/udev changes) and check: `systemctl --failed`, say "qué hora es".

## Keeping this repo up to date

`pip install --upgrade` of `hivemind-webchat` or `ovos-ocp-pipeline-plugin` overwrites the patched files: re-run
`./install/apply.sh hivemind` / `ovos`. After changing anything on the Pi, copy it back here; never copy real
`settings.json`, `proxy.env`, `open-webui/env` or `~/.config/hivemind-core/*.credentials` without replacing the
secrets with placeholders.
